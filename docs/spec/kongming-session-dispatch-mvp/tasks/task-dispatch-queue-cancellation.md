## ① 需求与变更

用户授权修复孔明审查报告中的两个 P1，并将功能缺失交给 qdev。B4 新增 feat01 场景3。真正移除排队消息时向孔明原会话回传一次取消。编辑和转入当前轮保留该笔委派。B3 按既有技术设计修复空正文终态。

需求与代码比较基线为独立插件仓 `7e425ac`，启动时工作区干净。功能变更入口为 [spec 正文](../spec.md#场景3-排队中的委派被移除)和 [changelog](../spec.md#changelog)。

## ② 精简技术设计

- D1 · 在 `followDispatch` 使用 DSH 公开的 `agent/inbox/discarded`。匹配目标 Agent 和消息 ID，在队列操作结束后读取待执行队列与领取状态。该消息仍在任一队列或已被领取时继续跟踪，实际移除时复用现有回传和释放入口。
- D2 · 沿用既有终态设计，缓存匹配轮次最后一条助手消息的可见正文，保留空正文。回传继续复用原生队列、来源 schema 和一次性释放。
- 规范 · R1 使用公开事件与原生队列，R2/R4/R5 沿用消息 schema、身份和来源，R7 以原生队列状态核对移除并沿用现有的一次回传守卫。R3 单一 TypeScript 运行时，R6 无新增阈值。代码和测试运行严格 TypeScript、typed ESLint 与格式检查。

## ④ 技术实现

- `packages/kongming/src/dispatch.ts` 的 `followDispatch` 跟踪最后一条助手消息，使用原生移除事件核对同 ID 消息是否仍在队列中，实际移除时通过 `deliver` 回传取消并通过 `release` 注销四个监听。
- `packages/kongming/test/dispatch.test.ts` 覆盖空正文、删除、编辑和转入当前轮。每项核对回传数量、会话及委派归属。
- `spec.md` 新增 feat01 场景3 和变化索引。本次实现及测试文件与计划一致。
