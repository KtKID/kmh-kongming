# 孔明创建会话委派查询与来源展示

用户通过孔明，把一次杭州天气预报查询交给新建的 DSH 普通会话，由 glm-5.3-flash 执行。孔明收到该会话的回复后答复用户。目标会话以紧凑、可展开的形式展示孔明与 Bot 的往来，用户与 Bot 的直接对话保持正常展示。

需求基线：2026-11-10 本次需求讨论。用户将第一版收敛为“孔明创建会话，让指定 glm-5.3-flash 查询杭州天气预报并回复”，随后对完整流程和界面验收明确答复“同意”。本文记录已确认的 MVP，开发与真实验收待执行。

## 本次目标与完成条件

- 本次目标与范围：验证孔明能创建一个普通会话，选择当前已有模型列表中的 glm-5.3-flash，发送杭州天气预报查询，接收回复并向用户作答；同时验证新会话可打开、发送者可区分、孔明往来可折叠及用户直接聊天的正常展示。
- 待验证假设：借助 DSH 已有会话能力，孔明能完成一次真实跨会话委派，用户能够在原有聊天界面查看过程和结果。

## feat01: 孔明委派天气查询并收回回复

用户给孔明一条要求，由孔明创建指定模型的会话完成查询，再向用户回复结果。

场景1: 新建指定模型会话完成杭州天气查询

必要性：用户明确要求第一版跑通孔明创建会话、指定 glm-5.3-flash 查询杭州天气预报并回复；缺少时本次跨会话委派假设无法得到验证。

- GIVEN 用户能够在真实网页中与孔明聊天，当前已有模型列表中的 glm-5.3-flash 可用，孔明拥有当前工作目录
- WHEN 用户向孔明发送“让 glm-5.3-flash 查询杭州天气预报”
- THEN 孔明创建一个可在 DSH 中打开的普通会话，选择 glm-5.3-flash，并沿用孔明当前工作目录
- THEN 新会话收到完整的查询要求及孔明来源说明，按 DSH 已有发送顺序处理，由所选模型完成实际查询并产生回复
- THEN 该回复自动交回孔明，孔明按 DSH 已有顺序继续处理，并向用户答复查询结果；两处会话的结果与本次委派记录可以相互核对

场景2: 指定模型不可用时明确呈现委派受阻

必要性：用户要求由指定模型真实执行，已有会话能力会报告模型不可用；实际模型可用性会影响本次查询，缺少检查会把未完成的指定模型委派误判为验证成功。

- GIVEN 用户能够与孔明聊天，本次指定的 glm-5.3-flash 当前不可用
- WHEN 用户要求孔明让 glm-5.3-flash 查询杭州天气预报
- THEN 用户能够得知指定模型当前不可用及本次委派受阻；验收记录保留原因，待指定模型恢复后通过真实查询确认成功

### 场景3 排队中的委派被移除

- GIVEN 孔明发出的委派仍在目标会话的待执行队列中。
- WHEN 用户从目标会话的队列中移除这条委派。
- THEN 孔明收到一次关联本次委派的取消通知，能够告知用户委派在执行前已取消。

用户编辑排队委派或将其转入当前轮时，同一条委派继续按原有队列行为处理并回传执行结果。

## feat02: 区分孔明往来与用户直接聊天

用户在目标会话中能识别孔明发起的交流，展开查看完整内容，并继续与该 Bot 正常聊天。

场景1: 查看并展开孔明与 Bot 的往来

必要性：用户要求孔明消息及对应回复一起折叠，来源可见，展开后能够查看；缺少时本次会话界面目标无法达成。

- GIVEN 孔明创建的新会话已经完成杭州天气预报查询
- WHEN 用户在 DSH 中打开该会话，并展开孔明往来记录
- THEN 该会话中的孔明请求与 Bot 对应回复默认合并为紧凑的折叠记录，折叠处能够识别孔明来源
- THEN 展开后显示完整请求与回复，内容与实际发送、查询和回复记录一致

场景2: 用户直接与同一 Bot 聊天

必要性：用户要求 Bot 继续正常与用户聊天，并明确用户直接对话正常展开；缺少时孔明往来展示可能影响原有聊天使用。

- GIVEN 用户已打开完成天气查询的目标会话，其中存在孔明往来的折叠记录
- WHEN 用户直接向该 Bot 发送一条普通聊天消息，并收到回复
- THEN 用户消息与 Bot 回复按 DSH 原有聊天方式正常展开，发送者显示为用户；孔明发起的往来继续保持独立的来源标识和折叠展示
