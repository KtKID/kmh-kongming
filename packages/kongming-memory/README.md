# kongming-memory-v1

## 概述

`@kmh/kongming-memory-v1` 为孔明提供稳定的冻结记忆。每次启动绑定孔明会话时，插件把原始记忆的当前完整内容发布为冻结记忆；原始为空时保留已有冻结版本。启用期间，每次模型提示词装配读取完整冻结正文，日常新增经孔明专属保存工具追加到原始文件。手动 `/compact` 成功后发布新版冻结文件，后续读取等待发布完成。

## 接入与记忆文件

本包与孔明主体同属一个 bundle：`@kmh/kongming` bundle 的[安装 patch](../kongming/cordis.patch.yml) 同时登记 `kmh-kongming` 与 `kongming-memory-v1` 两个实例，本包不再单独成 bundle。自定义 profile 在依赖中声明 `@kmh/kongming` 与 `@kmh/kongming-memory-v1` 两个包，在 `dsh.profile.bundles` 中只选择 `@kmh/kongming` 即可同时启用两者。记忆插件通过孔明公开 Agent 事件接入当前和后续会话。

文件使用服务端 home，KMH 启动器将 `KMH_HOME` 映射为 `DSH_HOME`。同一 home 下，两份文件各有职责。

| 文件                                   | 用途与更新时机                                                                               |
| -------------------------------------- | -------------------------------------------------------------------------------------------- |
| `$KMH_HOME/.kongming/MEMORY.md`        | 原始记忆；首次缺失时补齐为空文件，日常新增经孔明专属 `kongming_memory_save` 工具追加到末尾。 |
| `$KMH_HOME/.kongming/MEMORY.frozen.md` | 冻结记忆；启动绑定时按原始文件重发，原始为空时保留已有快照，每次装配完整读取。               |

原始记忆的日常修改与当前冻结版本相互独立。冻结的更新入口有两个：启动绑定孔明会话时按原始文件重发，以及手动 `/compact` 的成功回执；插件核对对应摘要与压缩提交记录后，将最新原始字节经临时文件完整替换为冻结文件。直接调用底座 `compactNow()` 的集成方需将成功结果传给公开服务的 `refreshFrozen(result)`。自动压缩与超限压缩的阶段归属见末尾开发备注。

冻结读取或发布失败时，错误包含具体路径，实际请求或服务调用收到失败。发布在临时文件完整写入后替换目标，发布失败保留完整的已有冻结版本。修复报错所指的文件访问问题后，可重新加载记忆插件以重新准备，再发送请求。

## 提示词配置

本包分别配置系统记忆上下文和任务收尾提醒。完整默认文案集中保存在[孔明 bundle 安装 patch](../kongming/cordis.patch.yml)，孔明自身的人格与身份由[孔明插件](../kongming/README.md#启动与配置)配置。

| 配置键           | Schema 默认值    | 内容与送达位置                                                                              |
| ---------------- | ---------------- | ------------------------------------------------------------------------------------------- |
| `promptTemplate` | 三项变量各占一行 | 文件路径说明与完整冻结正文，在 `system-prompt/assemble` 中形成系统提示词段落。              |
| `reminderPrompt` | 空字符串         | 普通任务收尾时的维护说明，通过 `agent.steer()` 进入同一轮的后续步骤；空或全空白时停用提醒。 |

`promptTemplate` 必须包含 `{{originalMemoryPath}}`、`{{frozenMemoryPath}}`、`{{frozenMemory}}`，分别填入原始路径、冻结路径和完整冻结正文。缺少变量、空模板或错误类型会使配置校验失败。变量替换只执行一次，冻结正文中的花括号、美元符号和其他模板样式保持原文。

`reminderPrompt` 支持 `{{originalMemoryPath}}` 与 `{{frozenMemoryPath}}`。默认安装文案包含“每次完成对话或完成任务后，把有价值的内容和踩坑记录到记忆文件里”，并说明先判断长期价值（寒暄、天气等无关紧要的内容不记录）、需要记录时调用 `kongming_memory_save` 追加一条可独立理解的新条目、该工具只能新增不能修改删除，以及按实际工具结果反馈。该文案在收尾事件中送达；系统记忆模板承担路径和冻结正文的装配。

## 收尾记录与写入权限

普通任务准备结束时，插件在 `agent/turn-stopping` 事件中追加一次 steer。这个时机位于 `turn/end` 之前，提醒继续当前轮的后续步骤。每个会话每轮最多提醒一次；历史消息和已接纳队列中的来源记录共同用于去重。该轮出现过 `max-tokens` 时跳过提醒，执行错误与取消沿实际循环的收尾处理。

模型接到提醒后，通过插件注册的孔明专属 `kongming_memory_save` 工具把新条目交给记忆服务；该工具仅追加、空白条目拒绝，不提供修改或删除已有记忆的入口，也只在孔明 Agent 作用域可用。工具在插件进程内经服务串行队列执行，直接写原始文件，不经过 DSH 文件沙箱，因此原始记忆位于项目工作区之外也不会触发逐次审批。长期价值选择由模型完成；保存结果以实际工具回执与文件内容为准，失败原因应向用户说明。

## 可选生命周期

记忆插件自行管理初始化、绑定、请求等待与清理。孔明基础准备独立完成；记忆启用后的文件准备和读取错误由记忆请求路径报告。

| 操作           | 对当前孔明会话的影响                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| 启用或后装记忆 | 访问已有 Agent，并监听后续绑定；冻结读取等待记忆准备与发布完成。                                       |
| 停用记忆       | 释放冻结装配、收尾提醒和压缩刷新监听，等待自身文件工作收敛；孔明实例、执行中任务、历史和记忆文件保留。 |
| 再次启用记忆   | 接回既有 Agent，按原始文件重发冻结并恢复后续装配与提醒。                                               |
| 停用孔明本体   | 孔明发布 Agent 分离事件，记忆释放该 Agent 的能力绑定；孔明执行的取消与保存由孔明生命周期管理。         |

已经发送的模型请求使用发送时的内容。卸载发生在冻结装配回调等待期间时，回调通过活动标记退出自身贡献，并保留其他插件的组装结果。卸载后重新发送的请求按当前插件集合装配，完整历史的处理见下一节。

## 卸载后的系统提示词与历史

“启用记忆 → 发送 A → 卸载记忆 → 同会话发送 B”需要分别检查最新系统提示词和 B 的完整请求。B 的新系统提示词由其余插件装配；会话历史按底座的投影与模型路由能力保留。

| 情况                                                          | B 的实际请求内容                                                                                                    |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 路由使用开头的系统提示词                                      | 底座替换有效系统内容，B 的系统消息采用卸载后的文本。                                                                |
| 路由声明 `systemPromptUpdate: in-history`，且继续同一请求序列 | 底座保留 A 的系统消息，并追加卸载后的完整系统消息。最新系统消息代表当前有效提示词，A 的冻结正文仍随旧系统消息携带。 |
| A 的回复、工具结果、压缩摘要或已处理提醒含记忆信息            | 相关内容作为仍被保留的会话历史进入后续请求；是否保留由实际上下文投影决定。                                          |
| 卸载前已有提醒进入待处理队列                                  | 该消息继续归 Agent 队列管理，后续消费沿既有队列规则进行。                                                           |

因此，**停止插件贡献与清除已携带的记忆是两项独立操作**。插件卸载保留会话文件、已有历史和队列；完整请求中的历史内容需要按会话与上下文规则另行处理。验收应检查实际发送的全部消息，并单独标记最新系统提示词中的记忆段落。

这两种系统更新路径由底座的 SystemPromptProjection 实现，路由声明与语义见 LLM 模型解析。模型是否仍能回答某条记忆，还取决于请求中保留的聊天、工具与摘要内容。

## 实现说明

<details>
<summary>文件发布、请求装配、收尾提醒与资源清理 — 点击展开</summary>

服务创建后，记忆插件通过孔明事件绑定当前和后续 Agent，并将文件准备放入自身队列。每次提示词装配等待队列完成，再读取完整冻结文件。普通任务收尾时，插件按会话与轮次检查来源记录，决定是否追加提醒。成功的手动压缩回执触发原始文件复制发布；卸载释放这些绑定并等待文件工作结束。

### 源码与构建

以下脚本分别承担配置、文件、事件和清理。公开服务定义在 `src/types.ts`，调用方据此取得两份路径并等待初始化、读取或刷新结果。

| 文件                                   | 作用、处理与关键函数                                                                                                                                                                                                                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [src/config.ts](src/config.ts)         | `Config` 校验三项必需模板变量与字符串类型，提供最小模板和空提醒默认值。                                                                                                                                                                                                       |
| [src/index.ts](src/index.ts)           | `apply()` 解析 home 并提供 `kongmingMemoryV1`；`createMemoryService()` 串行管理初始化、追加与发布，`readFrozen()` 等待队列，`bindAgent()` 接入四个功能，`close()` 释放绑定并等待自身工作。                                                                                    |
| [src/types.ts](src/types.ts)           | 定义 `MemoryFiles` 与 `KongmingMemoryV1` 服务，声明提醒来源中的会话 ID 和轮次，供装配、去重与调用方共用。                                                                                                                                                                     |
| [src/kongming.ts](src/kongming.ts)     | `mountKongmingMemory()` 订阅就绪、访问已有 Agent 和分离事件。每个 Agent 保留一份准备与释放记录，后装能力可接回原会话，清理函数幂等。初始化失败由读取路径和诊断日志报告。                                                                                                      |
| [src/files.ts](src/files.ts)           | `resolveMemoryFiles(home)` 校验绝对路径；`initializeMemoryFiles()` 补齐原始文件，并独占发布首次冻结；`appendOriginalFile()` 仅追加非空白条目并按需补分隔；`readFrozenFile()` 完整读取 UTF-8；`replaceFrozenFile()` 经同目录临时文件原子发布原始字节。文件错误保留路径和原因。 |
| [src/tool.ts](src/tool.ts)             | `mountMemoryTool()` 在孔明 Agent 作用域注册 `kongming_memory_save`；工具仅追加、限制调用方并返回保存回执，随绑定释放注销。                                                                                                                                                    |
| [src/prompt.ts](src/prompt.ts)         | `mountFrozenPrompt()` 为指定 Agent 绑定装配并返回清理函数。`assembleFrozenPrompt()` 委托现有段落，等待完整冻结读取，再单次替换模板；卸载活动标记覆盖等待前后，保留基础组装结果。                                                                                              |
| [src/steer.ts](src/steer.ts)           | `mountMemoryReminder()` 监听收尾并检查轮次保护；`hasMemoryReminder()` 检查历史和已接纳队列证据；`createMemoryReminder()` 填入路径并标注来源。文件维护由收到提醒的模型及通用工具执行。                                                                                         |
| [src/compaction.ts](src/compaction.ts) | `mountCompactionRefresh()` 根据成功回执的 `sourceEventSeq` 定位摘要，核对同一命令与压缩 ID 的 start/end；`refreshAfterCompaction()` 等待服务完整发布。清理等待已发起的刷新结束。                                                                                              |
| [build.ts](build.ts)                   | `buildPlugin()` 清理 `lib` 并调用严格 TypeScript 构建，输出运行代码和声明；编译失败向调用方保留诊断。                                                                                                                                                                         |
