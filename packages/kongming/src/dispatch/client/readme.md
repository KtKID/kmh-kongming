# dispatch/client/ 委派浏览器侧

> 草稿，待用户检查。模块总览、设计理念与使用方式见 [../../readme.md](../../readme.md)，委派宿主侧见 [../readme.md](../readme.md)。

目标会话中的委派请求和对应回复默认合并折叠，摘要显示「孔明 · 会话往来」及执行状态。孔明侧的回信显示「收到会话回信」，展开可见业务正文、附件或失败说明，孔明给用户的转述始终直接可见。用户直接发消息的轮次沿用宿主原生展示。[委派会话场景](../../../../../docs/spec/kongming-session-dispatch-mvp/spec.md#feat02-区分孔明往来与用户直接聊天)

### [projection.ts](projection.ts) — 委派事件投影

**功能**：`dispatchInput` 将原生会话日志中的追加委派和回信映射成 `kongming-dispatch` 聊天节点。来源兼容当前 `kmh-relay` 以及历史 `kongming-dispatch` 和 `kongming-reply`。

**实现原理**：`match()` 用来源 schema 独占匹配追加的 `user/message` 事件。`start()` 根据来源确定方向，展示时去掉已知的模型提示前缀，保留业务正文和终态说明。`buildViewNode()` 将委派请求归入 `exchange`，将回信归入 `input`。原始日志和模型上下文保留完整消息。[来源协议](../protocol.ts)

**设计取舍**：投影基于持久化的事件流而不是组件内存，页面刷新后折叠记录自动重建（对应技术设计[界面行为](../../../../../docs/spec/kongming-session-dispatch-mvp/tech-design.md#界面行为)）；只接管追加的委派消息，用户编辑等操作交给原生逻辑——普通用户消息不匹配来源 schema，天然继续走原生节点。

### [view.tsx](view.tsx) — 委派折叠视图

**功能**：`mountDispatchView(ctx)` 注册事件投影和折叠卡片。委派摘要显示「孔明 · 会话往来」及轮次状态，回信摘要显示「收到会话回信」。

**实现原理**：两种卡片展开时均复用宿主原生消息渲染器。委派卡片通过 `data-chat-turn` 折叠同轮回复和工具组，回信卡片的折叠范围限于回信正文。

**设计取舍**：复用原生渲染器保证 Markdown、图片、工具呈现与宿主一致，插件只加外壳；代价是 CSS 依赖当前 DSH 版本的 DOM 结构，DSH 升级后需要重新验收（技术设计[界面行为](../../../../../docs/spec/kongming-session-dispatch-mvp/tech-design.md#界面行为)明确记录了这一点）。折叠用原生 `<details>` 而不是状态管理，刷新后依然可开合。
